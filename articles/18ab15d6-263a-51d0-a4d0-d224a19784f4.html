물건의 바닥·손·손수레·작업대·판매 상태 전환과 쌓기 위치 관리

물건은 한 시점에 하나의 소유·배치 상태를 가져야 한다. 위치 좌표만으로 바닥과 손, 판매 완료를 구분하면 상태 충돌을 찾기 어렵다.

1. 개념을 연결해 이해하기

이동은 기존 상태의 유효성 확인, 새 위치 확보, 상태 전환을 한 흐름으로 처리한다. 쌓기 위치는 자리 점유와 충돌 검사를 함께 관리해야 한다.

2. 사례로 살펴보기

손수레에서 작업대로 옮길 때 작업대가 찼으면 물건은 원래 손수레에 남아야 한다. 실패했는데 소유 상태만 바뀌는 상황을 검증한다.

3. 주의할 점과 확인 방법

판매된 물건이 다시 잡히거나 두 장소에서 동시에 보이는 것은 단일 소유 규칙 위반이다. 화면 부모 노드 변경과 실제 소유 데이터 변경을 구분한다.

글 끝의 확인 질문

이동 도중 실패하면 원래 상태로 돌아가야 하는 데이터는 무엇인가?

글의 범위와 참고 자료

제공된 학습 주제를 바탕으로 작성한 개념 설명이다. 원본 프로젝트의 구현·수치·실행 결과를 확인한 보고서는 아니다. 사례는 실제 성과나 확정된 설정값을 뜻하지 않는다. 개념 연결과 사례는 이 학습 자료를 위해 작성한 설명·설계 제안이다. 실제 사업장 공정, 투자 판단, 제품 설정 및 서비스 공개 의무는 해당 조건의 자료로 별도 확인해야 한다.
