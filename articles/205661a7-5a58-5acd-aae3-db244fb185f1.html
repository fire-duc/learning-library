AI 에이전트에게 어디까지 맡길 것인가

서론

도서 예약 사이트에 검색 기능을 추가해 달라고 요청했다고 하자. AI가 버튼 이름을 정할 때마다 질문하면 작업이 느려진다. 반대로 오래된 예약 기록까지 마음대로 지우면 문제가 된다. 일을 맡기려면 목표뿐 아니라 스스로 결정해도 되는 범위와 멈춰야 할 조건을 함께 정해야 한다.

본론

1. 개념의 정의

AI 에이전트는 목표를 달성하기 위해 다음 행동을 판단하고 도구를 사용해 작업을 진행하는 시스템을 뜻한다. 문장을 생성하는 일 외에 파일 읽기, 코드 실행, 결과 확인 같은 행동이 포함될 수 있다.

자율 판단 범위는 사용자에게 매번 묻지 않고 결정해도 되는 영역이다. 도구 권한은 실행 환경에서 실제로 허용하는 접근·실행 범위다. “수정하지 말라”는 지침과 “쓰기 권한이 없다”는 제한은 서로 다르다.

완료 기준은 무엇이 충족되어야 요청을 마쳤다고 인정할지를 정한 조건이다. 중단 조건은 계속 진행하기 전에 사용자 판단이나 추가 준비가 필요한 상황이다. 둘을 함께 정해야 작업이 너무 일찍 끝나거나 범위를 넘어 계속되는 일을 줄일 수 있다.

2. 결정의 영향에 맞춰 자율성을 정한다

기존 코드 스타일에 맞는 변수 이름이나 내부 함수 배치처럼 요청 범위 안에서 쉽게 되돌릴 수 있는 선택은 자율적으로 처리할 수 있다. 반면 사용자 기록의 삭제 여부나 공개 범위처럼 결과에 큰 영향을 주는 불확실성은 먼저 해소해야 한다.

판단 기준을 “알아서 잘해라”로만 두면 어떤 선택이 중요한지 전달되지 않는다. 보존할 데이터, 변경할 기능, 검증 방법을 알려 주면 에이전트가 판단할 근거가 생긴다. 지침을 이해하더라도 실수할 수 있으므로 실제 접근 권한도 작업에 필요한 범위에 맞춰 두는 것이 좋다.

3. 사례로 살펴보기

가상의 도서 예약 사이트에서 검색어를 입력하면 제목에 맞는 책을 보여 주는 기능을 만든다고 하자. 기존 화면 스타일을 따르는 버튼 배치와 검색 로직 구현은 맡길 수 있다. 테스트용 책 데이터로 빈 검색어와 결과가 없는 경우를 검증하는 일도 요청 범위에 포함할 수 있다.

그런데 기존 예약 기록이 있으면 검색이 느리다는 이유로 그 기록을 삭제하려 한다면 다른 문제다. 검색 기능 추가 요청은 예약 데이터 삭제를 뜻하지 않는다. 데이터 보존 조건을 확인하고, 검색 방법을 바꾸거나 필요한 결정을 질문해야 한다.

완료 기준은 “코드 작성”만으로 잡기보다 “검색 결과와 빈 결과 처리가 확인되고, 실행 방법이 바뀌었다면 안내를 수정했다”처럼 결과로 표현한다. 검증 환경이 없어 실행하지 못했다면 구현 완료와 실행 확인을 구분해 보고한다.

4. 주의점과 확인 방법

모든 행동을 질문하도록 하면 작은 선택에서도 대기가 반복된다. 반대로 모든 행동을 허용하면 요청을 넘어선 변경을 통제하기 어렵다. 반복해서 발생하는 혼동을 보고 필요한 경계를 구체화하되, 이미 합의한 사소한 선택까지 다시 묻도록 만들 필요는 없다.

글로 쓴 규칙은 행동 판단을 안내하고, 도구 권한은 실제 가능한 행동을 제한한다. 예를 들어 테스트 환경에는 임시 데이터만 제공하고 운영 데이터에는 읽기 권한만 주면, 지침에만 의존하는 것보다 실행 범위가 분명해진다. 다만 이런 구성도 모든 오류를 막는다는 보장은 아니다.

결론

에이전트에게 일을 맡기는 기준은 “얼마나 많은 일을 시킬까”뿐 아니라 “어떤 근거로 결정하고 언제 멈출까”까지 포함한다. 자율 판단 범위, 도구 권한, 완료 기준, 중단 조건을 함께 정하면 작은 결정은 빠르게 처리하고 중요한 결정은 사용자가 통제할 수 있다.
