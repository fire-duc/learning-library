화면 업데이트 시 미저장 입력 보호와 오래된 데이터 표시

서론

사용자가 금액 입력란을 수정하는 동안 자동 새로고침이 기존 값으로 덮어쓴다면, 화면은 최신 상태가 됐어도 사용자의 작업은 사라진다.

본론

입력 중인 값과 서버에 저장된 값은 다르다

미저장 입력: 사용자가 바꿨지만 서버에 아직 확정하지 않은 값이다.

  • 서버에 저장된 설정과 잠시 다른 상태일 수 있다.

버전 충돌: 사용자가 편집하는 사이 다른 작업이 같은 자료를 변경해 기준이 어긋난 상황이다.

  • 어떤 값을 유지할지 판단이 필요하다.

자료 시각: 원본 값이 만들어진 때다.

  • 시세의 최신성을 판단할 때 확인해야 한다.

수신 시각: 화면이 자료를 받은 때다.

  • 방금 받은 오래된 자료도 있으므로 자료 시각과 구분한다.

시세는 갱신하되 작성 중인 입력은 보존한다

입력의 변경 여부와 서버 버전을 관리하고 저장 충돌을 알려야 한다. 화면 데이터에는 마지막 수신·원본 시각을 구분해 오래된 상태를 표시한다.

시세 영역은 새로고침하되 편집 중인 입력란은 유지하는 방식으로 나눌 수 있다. 저장할 때 기준 버전과 서버의 현재 버전이 다르면 충돌을 알려 선택하게 한다. 또한 연결 표시가 초록색이라는 이유로 시세까지 최신이라고 단정하지 않고 마지막 원본 시각을 함께 보여주는 것이 좋다.

사용자가 매수 금액을 바꾸는 동안 시세가 갱신돼도 입력은 유지한다. 다른 화면에서 설정이 저장됐다면 최신값으로 조용히 덮지 말고 충돌을 알린다.

연결 표시와 데이터의 최신성을 구분한다

시세가 오래됐는데 화면 애니메이션만 움직이면 최신으로 오해할 수 있다. 연결 상태와 데이터 시각을 별도로 표시하고 중요한 동작 직전 재확인한다.

결론

자동 갱신은 최신 서버 정보와 사용자의 편집 의도를 함께 보존해야 한다. 입력 상태와 자료의 신선도를 분리하면 조용한 덮어쓰기와 잘못된 최신성 인식을 줄일 수 있다.
