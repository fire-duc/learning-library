브라우저·서버·매매 워커·SQLite 장부의 역할

서론

가상의 거래 연습 화면을 닫았는데도 기록이 계속 쌓인다고 하자. 화면과 계산을 담당하는 프로그램이 서로 다른 곳에서 실행되기 때문에 가능한 동작이다.

본론

화면·서버·워커·장부의 역할을 나눈다

브라우저(Browser): 사용자가 보고 조작하는 화면을 실행하는 프로그램이다.

  • 브라우저 종료와 서버 종료는 같은 사건이 아니다.

서버(Server): 요청을 받아 필요한 작업이나 자료를 제공하는 프로그램이다.

  • 이 글에서는 화면의 명령을 확인하고 작업 결과를 제공하는 역할을 맡는다.

워커(Worker): 주기적인 감시나 오래 걸리는 처리를 맡는 실행 단위다.

  • 화면 요청이 들어올 때만 작동하는 처리와 구분할 수 있다.

SQLite 장부: SQLite 데이터베이스에 주문·체결·잔고 등의 상태를 기록한 저장소다.

  • 화면에 보이는 숫자와 별도로 지속적으로 보존할 근거를 둔다.

화면은 명령을 보내고 저장된 결과를 조회한다

화면을 닫아도 매매를 계속할지 여부는 워커의 생명주기에 달려 있다. 브라우저 표시와 서버 상태, 장부 확정 시점이 다를 수 있음을 고려한다.

브라우저가 명령을 보내면 서버는 권한과 요청 내용을 확인하고, 워커는 정해진 순서로 작업을 수행하며, 결과는 장부에 기록할 수 있다. 화면은 그 기록을 조회해 보여준다. 이렇게 나누면 화면을 새로고침했다고 주문을 다시 실행하지 않도록 설계하기 쉽다. 다만 역할을 나눴다는 사실만으로 중복 실행이 자동으로 막히지는 않는다.

사용자가 중지 버튼을 누르면 서버가 요청을 검증하고 중지 의도를 저장한 뒤 워커가 이를 반영한다. 화면은 응답을 받아 실제 반영 상태를 보여 준다.

역할을 나눴다고 중복 실행이 저절로 막히지는 않는다

이는 학습용 책임 분리 예시이며 특정 서비스의 실제 실행 구성을 뜻하지 않는다. 장부를 거치지 않는 화면 계산을 확정 상태로 취급하지 않는다.

결론

화면·요청 처리·반복 작업·기록의 역할을 구분하면 어떤 구성 요소가 멈췄는지 설명하기 쉽다. 거래의 기준 상태를 화면의 일시적인 표시만으로 관리하지 않는 것이 중요하다.
