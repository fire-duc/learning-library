서버 재시작과 사용자 중지 상태 보존

서론

사용자가 ‘중지’를 누른 뒤 PC를 재시작했는데 도구가 다시 매수를 시작한다면, 프로그램 복구가 사용자의 의도를 뒤집은 셈이다.

본론

1. 개념의 정의

사용자 의도 상태

사용자가 실행을 허용했는지 중지했는지 나타내는 정보다. 현재 프로세스가 살아 있는지와 구분해야 한다.

실행 상태

프로세스나 작업이 실제로 실행 중인지 나타내는 상태다. 실행을 허용했어도 오류로 멈춰 있을 수 있다.

영속 저장

프로그램이 종료돼도 다시 읽을 수 있도록 정보를 남기는 것이다. 메모리에만 둔 중지 여부는 재시작 시 사라질 수 있다.

2. 개념을 연결해 이해하기

실행 프로세스 상태, 사용자 요청 상태, 위험 중단 원인을 별도 저장하면 자동 시작 시 잘못된 재개를 줄일 수 있다.

복구 로직이 ‘프로세스가 없으면 무조건 시작’만 검사하면 의도적인 중지와 장애를 구분하지 못한다. 재시작 시 저장된 사용자 의도를 먼저 읽고, 실행이 허용된 경우에만 다른 안전 조건을 확인하도록 할 수 있다. 중지 버튼의 성공 안내도 상태가 실제로 저장된 뒤에 보여야 한다.

3. 사례로 살펴보기

사용자가 거래를 멈춘 뒤 서버가 재시작돼도 조회 화면은 복구하되 신규 진입은 중지 상태로 유지하는 정책을 생각할 수 있다.

4. 주의점과 확인 방법

메모리에만 저장한 중지 플래그는 재시작 때 사라진다. 상태 저장 실패와 초기값, 장부 접근 불가 때 신규 주문 허용 여부를 명시한다.

결론

재시작은 프로세스를 되살리는 사건이지 모든 행동을 다시 허용하는 명령이 아니다. 사용자 의도와 현재 동작을 분리해 저장하고 복구 순서에 반영하자.
