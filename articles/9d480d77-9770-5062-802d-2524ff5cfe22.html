전역 지침과 프로젝트 지침을 나누는 이유

여러 프로젝트에서 AI를 사용하면 공통 선호와 프로젝트 고유 규칙이 섞이기 쉽다. 이를 나누면 같은 규칙을 반복해서 복사하는 일을 줄이고, 프로젝트에 맞는 예외를 관리하기 편해진다.

1. 전역 AGENTS.md에는 공통 기준

전역 파일에는 모든 프로젝트에 적용할 사용자 선호와 기본 작업 원칙을 둔다. 예를 들어 외부 서비스에 진행 상황을 자동 기록하지 않는 원칙, 필요한 코드만 읽는 기준, 중요한 불확실성은 질문하는 기준이다.

Codex 공식 안내에 따르면 실행 시작 시 전역과 프로젝트 지침을 찾아 결합한다. 기본 Codex 홈의 AGENTS.override.md가 비어 있지 않으면 우선 사용하고, 그렇지 않으면 AGENTS.md를 사용한다. 프로젝트에서는 루트부터 현재 작업 디렉터리까지 지침을 찾는다. 따라서 명령마다 모든 파일을 직접 다시 읽는 방식으로 이해할 필요는 없다.

2. 프로젝트 AGENTS.md에는 고유 기준

프로젝트 파일에는 고유한 실행·검증 규칙과 문서 위치를 둔다. 공통 개발 원칙을 통째로 복사하기보다, 이 프로젝트의 테스트는 어떻게 실행하는지와 어떤 데이터에 접근하면 안 되는지 같은 정보를 적는 편이 유용하다.

공식 안내는 작업 위치에 가까운 지침이 앞서 결합된 지침보다 우선할 수 있다고 설명한다. 이는 AGENTS.md 파일 사이의 결합 규칙이다. 시스템의 권한 제한이나 사용자가 현재 요청한 내용을 모두 무시할 수 있다는 뜻은 아니다.

3. 충돌은 실제 행동으로 확인한다

전역에는 외부 자동 기록 금지가 있고 프로젝트에는 작업 후 Notion 동기화가 남아 있다고 가정하자. 두 문장이 같은 행동에 다른 결론을 내린다. 이런 경우 최신 사용자 의도를 확인하고 오래된 프로젝트 규칙을 정리해야 한다.

또 다른 예로, 일반 문서에는 작은 수정에서 파일 생성을 생략할 수 있다고 쓰고 학습 규칙에는 파일이 없으면 먼저 선택을 받도록 쓸 수 있다. 일반 문서 규칙이 학습 파일의 별도 규칙을 따른다고 연결하면 의도적인 예외로 이해할 수 있다.

4. 문서 역할을 분리한다

README는 사람의 사용·운영 안내서다. PROJECT_MAP은 읽을 코드와 검증 경로를 연결한다. DEVELOPMENT_PLAN은 현재 상태와 확정 결정, 남은 작업을 관리한다. LEARNING_TOPICS는 사용자의 학습 목록이다. 이 파일 이름들은 이번 프로젝트가 선택한 구성으로, 모든 도구가 요구하는 필수 파일 목록은 아니다.

지침을 수정한 뒤에는 현재 대화에 반영됐는지와 새 실행에서 불러오는 지침이 같은지 구분해 확인하는 것이 좋다. 다른 PC에 같은 파일이 자동으로 생기는 것도 아니다.
