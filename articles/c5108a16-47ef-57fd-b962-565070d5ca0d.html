SQLite 트랜잭션·잠금·읽기 전용 조회와 장부 일관성

서론

체결 내역은 저장됐는데 현금 차감은 저장되지 않았다면 장부에 실제보다 많은 돈이 남는다. 관련 변경을 하나의 단위로 확정해야 하는 이유다.

본론

1. 개념의 정의

트랜잭션

관련된 데이터 변경을 하나의 성공·실패 단위로 묶는 절차다. 일부 변경만 확정되는 상황을 막는 데 사용한다.

잠금

여러 작업이 충돌하는 변경을 동시에 수행하지 않도록 조정하는 장치다. SQLite는 한 시점에 한 작성자의 쓰기를 허용한다.

읽기 전용과 스냅샷

읽기 전용은 해당 연결에서 수정을 허용하지 않는 방식이다. 스냅샷은 특정 시점의 일관된 데이터 모습으로, 언제나 가장 최근 값이라는 뜻은 아니다.

2. 개념을 연결해 이해하기

잔고와 체결 기록을 같은 트랜잭션으로 반영하면 일부만 저장되는 문제를 줄일 수 있다. 읽기 전용 연결은 의도치 않은 쓰기를 줄이지만 조회 지연이나 오래된 스냅샷을 없애지는 않는다.

현금 차감과 체결 기록을 같은 트랜잭션으로 묶으면 둘을 함께 확정하거나 함께 취소할 수 있다. 다만 거래소 주문 자체는 데이터베이스 트랜잭션 밖에서 일어난다. 장부를 되돌렸다고 외부 주문도 취소되는 것은 아니므로 외부 결과와 내부 기록을 맞추는 대사는 여전히 필요하다.

3. 사례로 살펴보기

체결 기록은 저장됐는데 현금 차감이 실패하는 상태를 막기 위해 두 갱신을 묶는다. 긴 조회 트랜잭션은 새 변경을 즉시 보지 못할 수 있다.

4. 주의점과 확인 방법

WAL 사용이 다중 작성자의 무제한 동시 쓰기를 뜻하지 않는다. 잠금 대기·재시도와 트랜잭션 길이를 관리하고 외부 API 호출을 장시간 쓰기 잠금 안에 두지 않는다.

결론

트랜잭션은 내부 기록의 부분 저장을 막고 잠금은 충돌을 조정한다. 이 보장을 외부 서비스의 행동까지 자동으로 되돌리는 기능으로 확대 해석하지 않아야 한다.
