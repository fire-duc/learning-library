게임 개발 · 개발·운영

ID 기반 노드 재사용과 변경 감지로 게임 화면의 불필요한 재생성·갱신 줄이기

서론

가상의 창고 화면에 상자가 100개 있는데 하나의 위치만 달라졌다고 하자. 화면을 갱신할 때 상자 100개를 모두 지우고 다시 만들 수도 있지만, 달라진 상자만 고치는 방법도 있다. 후자를 사용하려면 무엇이 같은 물건이고 무엇이 바뀌었는지 판단할 기준이 필요하다.

본론

목록의 순서와 물건의 정체성은 다르다

고유 식별자(ID, Identifier): 같은 대상을 계속 가리키기 위해 사용하는 구분 값이다.

  • 정렬 후 세 번째 행의 물건은 달라질 수 있어도 상자 A의 ID는 유지한다.

노드 재사용(Node Reuse): 이미 존재하는 화면 노드를 같은 대상의 표현에 계속 사용하는 방법이다.

  • 위치만 달라졌다면 새 상자 노드를 만들지 않고 기존 노드의 위치를 바꿀 수 있다.

변경 감지(Change Detection): 이전에 반영한 상태와 현재 상태를 비교해 갱신할 필요가 있는지 판단하는 과정이다.

  • 위치가 같아도 종류·색·충돌 크기가 바뀌었다면 해당 변경을 확인해야 한다.

상태 목록과 화면 목록을 ID로 맞춘다

가상 화면의 상태 목록에는 A·B·C가 있고, 화면에도 같은 ID의 노드가 있다고 하자. 다음 상태가 A·C·D라면 B는 사라졌고 D가 새로 생겼다. A와 C는 같은 물건이므로 필요한 속성만 갱신한다.

ID 비교 결과 화면 처리 확인할 점
상태·화면 양쪽에 있음 기존 노드 갱신 같은 표현 종류를 사용할 수 있는가
상태에만 있음 새 노드 생성 초기 표시와 충돌 상태가 맞는가
화면에만 있음 기존 노드 제거 선택·참조도 함께 정리됐는가

상자 A가 전혀 다른 형태의 물건으로 바뀌었다면 ID가 같아도 노드 구성을 교체해야 할 수 있다. 따라서 ‘ID가 같으면 무조건 유지’가 아니라 ID와 표현 종류가 맞으면 재사용한다는 조건이 더 정확하다.

마지막으로 반영한 값도 무효화할 때가 있다

캐시 무효화(Cache Invalidation): 이전에 저장한 결과를 더 이상 현재 결과로 믿을 수 없을 때 버리거나 다시 계산하는 일이다.

  • 조명의 밝기가 마지막 적용값과 같으면 갱신을 생략할 수 있다. 하지만 조명 노드 자체가 새로 만들어졌다면 같은 밝기라도 다시 적용해야 한다.

상태 비교에서 빠뜨린 속성은 화면을 오래된 상태로 남길 수 있다. 선택 강조, 충돌 크기, 재질 변경처럼 실제 표현에 영향을 주는 항목을 함께 점검해야 한다. Godot에서는 노드 제거를 예약하는 queue_free()와 실제 제거 시점도 구분하므로, 제거를 요청한 노드에 대한 참조를 계속 사용하지 않도록 설계한다.

재사용이 곧 오브젝트 풀링은 아니다

오브젝트 풀링(Object Pooling): 사용하지 않는 객체를 보관했다가 다른 사용 요청에 다시 배정하는 방식이다.

  • 같은 물건의 노드를 계속 유지하는 것과, 사라진 물건의 노드를 보관해 다른 물건에 배정하는 것은 다르다.

여기서는 ID별 화면 동기화를 설명한다. 별도의 유휴 객체 보관소를 만들었다고 가정하지 않는다. 성능 개선도 물건 수·생성 비용·변경 빈도에 따라 달라지므로 생성 횟수와 프레임 시간을 전후 비교해야 한다.

결론

불필요한 재생성을 줄이려면 대상의 ID를 유지하고, 생성·갱신·제거를 구분해야 한다. 갱신을 생략하는 조건만큼 다시 갱신해야 하는 조건도 중요하다.
