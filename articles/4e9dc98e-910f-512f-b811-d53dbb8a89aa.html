로그인 기반 자동 복구와 전원·절전·인터넷 장애의 한계

서론

PC에 로그인하면 도구가 자동으로 켜지도록 설정했다고 하자. 그렇다고 전원이 꺼져 있거나 절전 중인 PC에서 계속 감시가 이루어지는 것은 아니다.

본론

1. 개념의 정의

로그인 기반 시작

사용자 로그인이라는 사건을 계기로 프로그램을 실행하는 방식이다. 운영체제 부팅 직후 실행과 조건이 다를 수 있다.

복구와 가용성

복구는 중단 뒤 동작을 되살리는 과정이고, 가용성은 필요한 때 기능을 사용할 수 있는 정도다. 자동 시작 기능 하나가 전체 가용성을 보장하지 않는다.

장애 조건

전원·절전·네트워크·인증 등 실행을 막는 환경 조건이다. 서로 다른 원인이므로 대응 방법도 다르다.

2. 개념을 연결해 이해하기

복구 조건을 프로세스, 운영체제 세션, 전원, 네트워크로 나눠 보면 적용 범위를 설명하기 쉽다. 복구 뒤에는 상태 확인과 주문 대사가 필요하다.

로그인하지 않으면 시작하지 않는 설정이라면 재부팅만으로는 작업이 재개되지 않는다. 또 프로그램이 켜져 있어도 인터넷이 끊기면 외부 상태를 확인할 수 없다. 복구 후에는 마지막 기록과 외부 주문을 맞춰야 하므로 단순히 실행 파일을 띄우는 것보다 복구 절차가 길 수 있다.

3. 사례로 살펴보기

로그인 뒤 워커가 자동 시작해도 인터넷이 끊겼다면 시세와 주문 확인은 실패할 수 있다. 네트워크 복구 후 미확인 주문을 대사한 뒤 재개 조건을 검사한다.

4. 주의점과 확인 방법

절전 복귀와 재부팅은 서로 다른 시험이다. 자동 복구가 사용자의 중지 상태를 덮어쓰지 않게 하고 실제 PC에서 각각 확인해야 한다.

결론

자동 실행의 시작 조건과 실행 후 검증 범위를 구분하자. 로그인·재부팅·절전 복귀·통신 회복을 각각 시험해야 어떤 상황까지 복구되는지 알 수 있다.
