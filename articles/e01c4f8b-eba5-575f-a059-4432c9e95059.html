단일 워커·통신 타임아웃·종목별 장애 격리의 한계

서론

여러 종목을 순서대로 확인하는 워커가 첫 종목의 응답을 오래 기다린다면 나머지 종목도 함께 늦어진다. 예외를 잡았다는 사실만으로 지연이 격리되는 것은 아니다.

본론

1. 개념의 정의

단일 워커

하나의 실행 주체가 작업을 담당하는 구조다. 중복 실행을 관리하기 쉽지만 순차 처리라면 앞 작업의 대기가 뒤에 영향을 준다.

타임아웃

응답을 기다리는 최대 시간을 정한 것이다. 대기를 끝낸다는 뜻이며 상대 서버의 처리까지 취소됐다는 뜻은 아니다.

장애 격리

한 대상의 실패가 다른 대상의 처리를 불필요하게 멈추지 않도록 경계를 두는 것이다. 공통 네트워크 장애처럼 공유 원인은 별도 대응이 필요하다.

2. 개념을 연결해 이해하기

종목별 오류를 분리하고 제한된 재시도를 적용할 수 있다. 그러나 공유 자원 고장이나 전체 API 장애는 종목별 격리만으로 해결되지 않는다.

가격 조회의 타임아웃은 다음 대상 조회로 넘어갈 수 있지만, 주문 전송의 타임아웃은 상대가 이미 처리했을 가능성을 남긴다. 따라서 같은 오류 이름이어도 후속 행동이 다르다. 무조건 재시도하면 주문이 중복될 수 있고, 무한히 기다리면 다른 보호 판단이 멈추므로 대기 한도와 결과 대사를 함께 설계한다.

3. 사례로 살펴보기

한 종목 조회가 지연되면 제한 시간 뒤 다음 종목으로 넘어가되 주문 요청이었다면 미확인 상태로 남겨 대사한다. 조회 실패와 주문 불확실성을 다르게 처리한다.

4. 주의점과 확인 방법

너무 짧은 제한 시간은 정상 응답도 실패로 만들고 너무 길면 보호 감시를 막는다. 실제 지연 분포를 보고 설정하며 무한 재시도를 피한다.

결론

타임아웃은 기다림을 제한하고 대사는 불확실한 결과를 확인한다. 두 역할을 구분해야 속도와 중복 방지를 함께 다룰 수 있다.
