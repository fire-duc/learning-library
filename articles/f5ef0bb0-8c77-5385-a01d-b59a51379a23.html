AI 작업 지침의 개선 효과를 측정하는 방법

지침을 정리한 뒤 “효율이 20% 좋아졌다”고 말하려면 무엇을 측정했는지 설명할 수 있어야 한다. 느낌에 따른 평가는 개선 방향을 잡는 데 쓰고, 절감 효과를 입증하려면 비교 가능한 기록이 필요하다.

1. 무엇을 줄였는지 나눠 본다

전체 소요 시간은 요청부터 완료까지의 시간이다. 이 안에는 AI 실행 시간, 사용자 답변 대기, 학습 대기도 포함될 수 있다. 따라서 실행 시간과 대기 시간을 따로 기록하면 지침의 영향을 이해하기 쉽다.

도구 호출 수는 파일 읽기·검색·검증 등의 호출 횟수다. 호출이 줄어도 한 번의 출력이 매우 커지면 입력 문맥량은 늘 수 있다. 호출 수만으로 비용을 판단하면 안 된다.

재작업은 처음 요청의 오해나 오류를 고치기 위한 추가 작업이다. 사용자가 새 기능을 추가한 경우는 재작업과 분리한다. 품질은 요구사항 충족과 필요한 검증 통과 여부로 확인한다.

2. 비교 조건을 맞춘다

오탈자 수정과 데이터 구조 변경을 한 묶음으로 비교하면 결과가 왜곡된다. 비슷한 난이도의 작업끼리 묶고 모델, 추론 설정, 프로젝트 상태, 검증 범위를 기록한다. 같은 작업을 두 번 하면 두 번째 작업이 이미 정보를 알고 있어 빨라지는 효과도 고려해야 한다.

몇 건만으로 보편적인 절감률을 단정하지 않는다. 여러 작업의 중앙값과 편차를 함께 보면 특정 작업 하나가 평균을 크게 바꾼 경우를 알아보기 쉽다.

3. 계산 예시

다음은 실제 측정이 아닌 계산 설명용 가상 예시다.

변경 전: 실행 12분, 대기 3분, 전체 15분, 도구 호출 20회. 변경 후: 실행 9분, 대기 1분, 전체 10분, 도구 호출 14회.

전체 시간 감소율 = (15 - 10) / 15 × 100 = 약 33.3%. 실행 시간 감소율 = (12 - 9) / 12 × 100 = 25%. 도구 호출 감소율 = (20 - 14) / 20 × 100 = 30%.

이 수치를 더해서 88.3% 개선이라고 말할 수는 없다. 서로 겹치는 서로 다른 지표다. 과금도 실제 사용량과 가격 체계가 있어야 계산할 수 있다.

4. 속도와 품질을 함께 본다

테스트를 생략해 빨라진 결과와 같은 품질을 유지하며 반복 읽기만 줄인 결과는 구분해야 한다. 완료 기준을 동일하게 유지한 상태에서 시간을 비교해야 유용하다.

학습 미완료 시 중단은 속도를 높이는 정책이 아니다. 사용자의 이해와 통제를 우선하는 정책이므로 학습 대기는 따로 기록하고 목적 달성 여부로 평가한다.

간단한 기록 양식

작업 유형 / 모델·설정 / 실행 시간 / 대기 시간 / 도구 호출 / 재작업 / 요구사항 충족 / 검증 결과

이 양식은 측정 방법의 제안이며 외부 서비스 자동 기록을 뜻하지 않는다. 이번 프로젝트에서는 측정 결과가 아직 없다.
