AI 작업 지침의 개선 효과를 측정하는 방법

서론

AI에게 “필요한 파일부터 확인하라”는 지침을 추가했더니 작업이 빨라진 것 같다고 하자. 정말 지침 덕분일까? 이번 작업이 더 쉬웠거나 이미 내용을 알고 있었을 수도 있다. 개선 효과를 판단하려면 무엇을 줄였는지와 무엇을 같은 조건으로 비교했는지를 나눠 살펴봐야 한다.

본론

1. 개념의 정의

평가 지표는 결과를 비교하기 위해 관찰하는 값이다. 완료까지 걸린 시간, 도구 호출 횟수, 오류를 고친 횟수 등이 해당한다. 기준선은 개선 전의 비교 기준이다. 기준선이 없으면 빨라졌다는 느낌은 있어도 감소율을 계산하기 어렵다.

재작업은 처음 요청을 잘못 이해하거나 구현에 오류가 생겨 다시 하는 작업이다. 사용자가 새 기능을 추가로 요청한 것은 범위가 늘어난 것이므로 재작업과 구분한다.

통제 조건은 비교할 때 가능한 한 같게 유지하는 조건이다. 작업 난이도, 사용하는 모델과 설정, 시작 시 제공한 정보, 완료를 인정하는 기준이 여기에 포함된다.

2. 속도와 품질을 함께 비교한다

전체 소요 시간에는 AI가 실제로 처리한 시간뿐 아니라 사용자 답변을 기다린 시간도 포함될 수 있다. 실행 시간과 대기 시간을 나누면 어디서 변화가 생겼는지 알기 쉽다. 도구 호출 수가 줄어도 한 번에 읽는 내용이 크게 늘었다면 비용까지 줄었다고 단정할 수 없다.

비교할 때는 같은 품질을 요구해야 한다. 필요한 테스트를 생략해 5분 빨라진 결과와, 중복 읽기만 줄여 5분 빨라진 결과는 의미가 다르다. 먼저 요구사항과 검증 결과를 확인하고, 그 조건을 충족한 작업끼리 시간과 사용량을 비교한다.

3. 사례로 살펴보기

가상의 도서 검색 화면을 수정하는 비슷한 작업들을 비교한다고 하자. 아래 값은 실제 측정이 아니라 계산 방법을 설명하는 예시다.

지표 개선 전 개선 후 감소율
실제 실행 시간 12분 9분 25%
답변 대기 시간 3분 1분 약 66.7%
전체 시간 15분 10분 약 33.3%
도구 호출 20회 14회 30%

감소율은 (개선 전 - 개선 후) ÷ 개선 전 × 100으로 계산한다. 전체 시간이 15분에서 10분이 되었으므로 5분을 줄였고, 기준인 15분의 약 33.3%다. 기준값이 0이면 이 방식으로 감소율을 계산할 수 없다.

위 비율들을 더해 전체 개선율이라고 부르면 안 된다. 전체 시간에 실행과 대기가 이미 포함되어 있고, 도구 호출은 시간과 단위도 다르기 때문이다. 비용 감소율은 실제 사용량과 요금을 별도로 확인해야 한다.

4. 주의점과 확인 방법

동일한 작업을 두 번 하면 두 번째에는 이미 답이나 파일 위치를 알고 있을 수 있다. 이런 학습 효과를 지침의 효과로 오해하지 않도록 시작 조건을 기록하고, 비슷한 작업을 여러 건 비교한다. 결과가 들쭉날쭉하면 값들을 크기순으로 놓았을 때 가운데에 오는 중앙값과 결과의 퍼진 정도를 함께 살펴볼 수 있다.

기록은 작업 유형, 모델·설정, 실행·대기 시간, 재작업, 요구사항 충족, 검증 결과 정도로 시작할 수 있다. 이 기록 양식은 평가 방법의 제안이며 자동으로 외부 서비스에 저장하라는 뜻은 아니다. 몇 건의 결과만으로 다른 모든 프로젝트에서도 같은 절감률이 나온다고 일반화하지 않는다.

결론

좋은 개선은 필요한 품질을 유지하면서 불필요한 작업을 줄이는 변화다. 시간·호출·비용을 각각 측정하고, 비교 조건을 맞춰야 무엇이 나아졌는지 설명할 수 있다. 추정치는 실험 방향을 정하는 데 활용하고, 실제 효과를 말할 때는 측정한 범위와 결과를 제시한다.

범위와 참고 자료
