개발·운영

Windows 실행본 제작·배포 파일 구성·라이선스 포함·사용자 저장 보존

서론

개발 PC에서는 잘 실행되는 게임을 다른 사람에게 전달했는데 파일이 없다는 오류가 난다고 하자. 실행 파일 생성과 배포 준비가 같은 단계가 아니라는 사례다.

본론

1. 개념의 정의

내보내기

개발 도구의 프로젝트를 사용자가 실행할 수 있는 형태로 만드는 과정이다. 대상 운영체제와 포함할 자원을 선택한다.

배포 구성

실행에 필요한 프로그램·자원·안내·라이선스를 묶은 것이다. 구성에 따라 자원이 실행 파일 안에 있거나 별도 파일에 있을 수 있다.

사용자 저장

설치된 게임 파일과 별개로 플레이 과정에서 생성하는 진행 데이터다. 새 버전 교체로 지워지지 않도록 위치와 절차를 구분한다.

2. 개념을 연결해 이해하기

Godot Windows 내보내기에는 실행 파일과 프로젝트 데이터가 필요하며 설정에 따라 배치가 달라진다. 엔진과 사용 자산의 라이선스는 각각 확인해야 한다.

개발 폴더에서 실행하면 우연히 남아 있는 자원 파일 덕분에 오류를 발견하지 못할 수 있다. 그래서 전달할 묶음만 새 위치에 풀어 실행해야 한다. 업데이트도 실행 파일 교체와 저장 데이터 보존을 나눠 확인하고, 사용한 엔진·폰트·음원 등의 라이선스 요구를 각각 확인한다.

3. 사례로 살펴보기

깨끗한 테스트 폴더에서 실행하고 새 저장을 만든 뒤 새 버전 배포 파일로 교체해 저장이 유지되는지 확인한다. 설치 폴더와 사용자 저장 위치는 구분한다.

4. 주의점과 확인 방법

개발 PC에서 실행됐다고 새 환경에서 검증된 것은 아니다. 자산 누락, 렌더러 호환성, 권한, 라이선스 안내와 기존 저장 호환성을 점검한다.

결론

배포 완료는 파일을 만든 순간보다 수신자가 그 묶음으로 실행하고 기존 진행을 유지할 수 있는 상태에 가깝다. 깨끗한 위치에서 실행·자료 누락·저장 보존을 확인하자.

읽고 확인할 질문
