화면 없는 로직 검사·장면 검사·실제 렌더 입력 검사의 역할과 한계

서론

자동 검사에서는 모두 통과했는데 실제 게임 화면에서 버튼을 누를 수 없다면 검사가 잘못된 것일까? 검사한 범위가 화면 입력까지 포함하지 않았을 수 있다.

본론

1. 개념의 정의

로직 검사

계산과 상태 변경 규칙을 확인하는 검사다. 판매 합계나 중복 보상 방지처럼 화면 없이도 판단할 수 있는 내용을 다룬다.

장면 검사

장면을 불러왔을 때 필요한 요소와 연결이 유효한지 확인한다. 파일 경로나 노드 참조 오류를 찾는 데 도움이 된다.

렌더·입력 검사

실제로 화면을 그리고 마우스나 키 입력으로 조작하는 검사다. 가림·크기·초점·클릭 위치처럼 논리 결과만으로 알기 어려운 문제를 다룬다.

2. 개념을 연결해 이해하기

검증을 여러 층으로 나누면 실패 원인을 좁히기 쉽다. 계산 검사가 통과해도 카메라 가림이나 UI 클릭 전달 문제는 실제 화면에서 남을 수 있다.

계산 검사가 판매 금액을 확인해도, 판매 버튼 위를 다른 패널이 덮고 있는지는 알 수 없다. 장면을 성공적으로 불러와도 카메라가 바닥을 보고 있으면 플레이할 수 없다. 따라서 변경한 내용이 어느 층에 영향을 주는지 판단하고, 그 층의 실제 결과를 확인해야 한다.

3. 사례로 살펴보기

판매액 계산과 중복 지급은 로직 검사로, 누락 노드는 장면 로딩으로, 3D 부위 클릭은 실제 카메라·해상도로 확인한다.

4. 주의점과 확인 방법

headless 실행을 실제 사용자 경험의 증거로 쓰면 안 된다. 반대로 모든 계산 오류를 사람이 화면에서만 찾는 것도 비효율적이다. 변경 영향에 맞춰 조합한다.

결론

검사는 종류마다 답할 수 있는 질문이 다르다. 화면 없는 검사를 빠르게 활용하되, 보이고 조작되는 경험까지 확인한 것으로 확대 해석하지 않아야 한다.
